## Authority and limits

Hosted selected GET uses the existing fresh OBO dispatcher, verified committed registry membership, exact package activation, artifact hashes and complete queried scope inventories. It materializes canonical package inputs only, then reads selected proposal/review/document/run/job/loop metadata directly through Delta. It never restores full execution/audit databases, XML, unrelated packages, model routes or checkpoint history. Immutable campaigns live outside content generations; discovery verifies their exact original owner/project/package envelopes through the existing CampaignStore/Delta adapter. No local hosted fallback, SQL authority, provisioning or content-generation write is added. The exact GET route is also accepted by the existing durable observational-read router.

Evidence is bounded to 2,000 records per family and 8 MiB decoded aggregate. Hosted overflow fails closed. Local bounded samples cannot establish totals/freshness. Workflow pagination does not turn a sampled historical count into a complete total. All freshness depends on the full existing advisory snapshot contract (including documents, reviews, policy, skills and analysis overlay), not package hash alone.

Navigation uses the existing package-understanding prerequisites and next-action guidance. Scope/scenario changes and page departure discard pending responses and clear old evidence. Accessible native SVG charts include count labels, legends and text alternatives; workflow identifiers and detailed receipts are collapsible. No new dependency is required. Existing hosted staging includes the module and static assets automatically; packaging is not deployment.

The requested agentic-blueprint documents/PDF are absent from this checkout. The available proposal-first plan and hosted Delta-authority design were consulted. Offline tests do not guarantee live OBO latency, full business execution or production parity.
